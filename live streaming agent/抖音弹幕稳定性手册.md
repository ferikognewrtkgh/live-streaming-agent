# 抖音弹幕链路稳定性手册

本手册涵盖 DouyinBarrageGrab + barrage_adapter 整套链路的运维要点。
按 **生产事故频次倒序** 排列。

---

## 1. DouyinBarrageGrab 频繁断连 / 抓不到弹幕

### 1.1 启用 forcePolling 模式（最关键）

DouyinBarrageGrab 默认走 **系统代理 + WebSocket 劫持** 模式（叫 hook 模式）。
这个模式延迟低（~50ms），但对 Chrome 版本敏感：

- Chrome 升级后证书可能失效
- 部分 Chrome 安全策略会阻止劫持
- 抖音直播伴侣升级会换协议
- 反爬虫机制会主动断流

**改用 forcePolling 模式可以彻底绕过这些坑**：
它是定时主动从 Chrome DevTools Protocol 拉取弹幕，对 Chrome 版本完全不敏感。
代价是延迟从 ~50ms 升到 ~500ms，对 VTuber 场景完全可接受。

**操作步骤**：
1. 关闭 WssBarrageService.exe
2. 编辑 `WssBarrageService.exe.config`
3. 找到 `<appSettings>` 节点，加入或修改：
   ```xml
   <add key="forcePolling" value="true"/>
   ```
4. 保存重启

启动后控制台应能看到 `polling mode enabled`、`connected to chrome debugger` 字样。

### 1.2 系统代理冲突

DouyinBarrageGrab 会设系统代理。如果同时开 **V2RayN / Clash / 公司 VPN**，会抢代理导致两边都坏。

**解决方案 A：进程级过滤（推荐）**

在 `WssBarrageService.exe.config` 配 `ProcessFilter`，只对 chrome.exe 生效：
```xml
<add key="ProcessFilter" value="chrome.exe;DouyinLiveCompanion.exe"/>
```

**解决方案 B：用 forcePolling**

forcePolling 模式不依赖系统代理，可以和任何 VPN 共存。

### 1.3 启动顺序固化

错误做法：先开 Chrome 进直播间，再开 DouyinBarrageGrab → 经常抓不到。

**正确顺序**：
1. 启动 `WssBarrageService.exe`
2. 等控制台出现 `Service started, listening on 8888`
3. 再打开 Chrome，进抖音直播间
4. 启动 vtuber-demo server

## 2. 适配器配置调优

### 2.1 默认配置（推荐起点）

`server.py` 里启动 adapter 时的默认配置：

```python
barrage_config = BarrageConfig(
    ws_url="ws://127.0.0.1:8888",
    consume_interval=3.0,         # 弹幕模式: 每条间隔
    custom_consume_interval=3.0,  # 自定义模式: 每条间隔
    custom_item_ttl=10.0,         # 自定义模式: TTL
    gift_trigger_min_diamonds=10000,  # 礼物触发门槛 (1万抖币)
    gift_combo_window=3.0,        # 连击合并窗口
    gift_combo_max_wait=8.0,      # 连击最长缓冲
    stale_warn_seconds=30.0,      # 30s 无消息告警
    stale_force_reconnect_seconds=60.0,  # 60s 无 Type=8 心跳即重连
    diamond_max_users=10000,      # 钻石累计 LRU 上限
    welcome_enabled=False,        # 默认不开欢迎语
    follow_enabled=False,         # 默认不开关注感谢
)
```

### 2.2 不同场景的调整

**冷场 / 小直播间**：
- `welcome_enabled=true` + `welcome_batch_window=3` → 每个进直播间的都欢迎，提升互动感
- `follow_enabled=true` → 每个关注都感谢
- `consume_interval=2.0` → 反应更快
- `min_content_length=1` → 不过滤短消息

**爆款 / 大直播间**：
- `welcome_enabled=false` → 关闭欢迎，否则刷屏
- `consume_interval=5.0` → 慢一点避免话题切换太快
- `min_content_length=3` → 过滤"6/666/dd"等水弹幕
- 启用自定义模式 + `wealth>=10` 或 `diamond_rank>=1000` → 只回大哥/粉丝团

**所有调整都可以热更新**（不用重启）：
```bash
uv run python barrage_custom.py config-set consume_interval=2.0 welcome_enabled=true
```

## 3. 监控与排障

### 3.1 实时监控

直播开播时，每 5-10 分钟跑一次：
```bash
uv run python barrage_custom.py metrics
```

关注指标：
- **`recv` 速率**：< 0.1 条/秒 → 大概率断流，检查 DouyinBarrageGrab
- **`recv` vs `enqueue` 差异大**：filter 过滤太多，看 `custom_filtered_total`
- **`consume` 接近 0 而 `enqueue` 高**：消费跟不上，调大 `consume_interval` 或队列上限
- **`queue_age_p95 > 30s`**：弹幕积压严重，需要降低过滤门槛或增加消费速率
- **`reconnect_count` 持续增长**：连接不稳，检查 forcePolling 配置

### 3.2 常见故障模式

| 现象 | 可能原因 | 排查命令 |
|------|----------|----------|
| 完全收不到弹幕 | DouyinBarrageGrab 死了 / 没连上抖音 | `barrage_custom.py metrics` 看 `recv=0` |
| 收到但不消费 | VTuber 不在 BARRAGE 模式 | `switch_mode.py barrage` |
| 收到但全被过滤 | filter 阈值太严 / 自定义模式阈值太高 | `metrics` 看 `filter_drop` 速率 |
| 礼物没反应 | `gift_trigger_min_diamonds` 太高 | `config-set gift_trigger_min_diamonds=100` |
| 大哥连击只回一条 | 这是预期 (B1 礼物连击合并) | 等连击结束统一回复 |
| AI 一直回小号水弹幕 | 没开自定义筛选 | `barrage_custom.py set wealth:15` |
| 直播间切换后排行没清 | 钻石累计是跨场的 | `barrage_custom.py reset-diamond` |

### 3.3 日志关键字

| 关键字 | 含义 |
|--------|------|
| `[barrage] ✅ 收到第一条消息` | 连接成功 |
| `[barrage] ⚠️ 连接假活` | 心跳超时，自动重连 |
| `[barrage][gift] 连击缓冲新建/累加/入队` | 礼物合并流程 |
| `[barrage][custom] 过滤丢弃 wealth=X<阈值` | 自定义筛选过滤了某条 |
| `[barrage][welcome] 进直播间合并入队` | B3 欢迎语已生成 |
| `[barrage][diamond] LRU 淘汰` | 钻石用户超过上限，最老的被踢 |
| `[barrage][config] 热更新生效` | B4 运行时配置已应用 |

## 4. 切换直播间

### 推荐流程

```bash
# 1. 切到 sleep 模式 (VTuber 不再回复)
uv run python switch_mode.py sleep

# 2. 重置钻石累计
uv run python barrage_custom.py reset-diamond

# 3. 在 DouyinBarrageGrab 那边切直播间 (浏览器刷新到新直播间页面)

# 4. 验证新直播间的弹幕流入
uv run python barrage_custom.py metrics
# 应该能看到 recv > 0

# 5. 切回 BARRAGE 模式
uv run python switch_mode.py barrage
```

## 5. 长时间运行建议

### 5.1 资源监控

- 钻石用户字典上限 `diamond_max_users=10000` (单条 ~50 字节, 上限内存 ~500KB)
  - 超出会 LRU 淘汰最老用户, 日志会 WARN
  - 想更大: `config-set diamond_max_users=50000`

- 礼物连击缓冲一般 < 100 个 key, 由 `gift_combo_max_wait` 上限保证不会无限增长

- 进直播间/关注缓冲会被 `welcome_batch_window` / `follow_batch_window` 自动 flush

### 5.2 推荐运维节奏

- 开播前: `metrics` 看一次连接是否正常
- 直播中每 30 分钟: 看一次 `metrics`，关注 `reconnect_count` 是否在涨
- 下播时: `reset-diamond` 清零（如果不想跨场累计）

### 5.3 进程异常退出

如果配置了自动重启（`grab_auto_restart=true` + `grab_exe_path` 指向 exe），
adapter 检测到 DouyinBarrageGrab 进程不在就会自动拉起。
默认配置是 OFF，因为系统代理类工具一般不希望自动启动。

## 6. 命令速查

```bash
# 模式切换
uv run python switch_mode.py sleep|co_host|barrage|punish

# 自定义筛选
uv run python barrage_custom.py set wealth:15:0 fan_badge:5:1 diamond_rank:1000:2
uv run python barrage_custom.py off
uv run python barrage_custom.py status

# 钻石排行
uv run python barrage_custom.py top         # 全部
uv run python barrage_custom.py top 10      # 前10
uv run python barrage_custom.py reset-diamond

# 监控
uv run python barrage_custom.py metrics

# 配置热更新
uv run python barrage_custom.py config-get
uv run python barrage_custom.py config-set consume_interval=4 welcome_enabled=true
```
